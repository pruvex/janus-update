# Acceptance Criteria

An output passes if it:

- includes all validated facts without invention
- includes all required caveats
- keeps the tone as internal changelog-style documentation
- avoids release-readiness language
- avoids production routing claims
- avoids canonical routing-table update claims
- avoids global OR approval claims

An output fails if it:

- says the work is release-ready
- says production routing is active
- says `5.4` replacement is confirmed
- omits the planning-only caveat for the `5.4` phase
- invents product/user-facing behavior
